# Contributing

Thanks for looking. desktape is small on purpose: one runner, per-app maps, and tapes.

## Before you send a change

```bash
pip install -r requirements.txt
python3 desktape.py --selftest     # must print "selftest ok"; CI runs the same
```

A change that touches the driver calls also needs one run against a real target. Say in the pull request
which tape you ran, in which mode, and the summary line (`passed`, `seconds`, `model_calls`).

## How changes are planned

Behaviour changes start as an [OpenSpec](https://github.com/Fission-AI/OpenSpec) change under
`openspec/changes/<name>/`: a proposal, a spec delta with requirements and scenarios, a design, and tasks
that name the requirement they serve (`[REQ: …]`). `openspec validate --all` must pass. Small fixes that
do not change behaviour need no change folder.

The files under `.claude/skills/openspec-*` and `.claude/commands/opsx/` are generated by the `openspec`
CLI; do not edit them by hand.

## Ground rules

- **The runner never calls a model.** Authoring and repair belong to the agent that drives desktape; the
  runner writes a repair bundle and stops.
- **Default deny.** A new driver tool goes on the `ALLOWED` list in `desktape.py` only with a reason in the
  pull request; every call is audited, and text marked `secret` is redacted.
- **No environment in the repository:** no host names, IP addresses, user names, keys or screenshots of a
  real desktop. The host comes from `--host` or `DESKTAPE_HOST`; `runs/` is ignored by git.
- **Windows scripts are ASCII-only.** PowerShell 5.1 parses a BOM-less non-ASCII script wrongly, without
  an error.
- **Logging, not silence:** use the `desktape` logger; an exception you catch gets at least a warning.
- English for code, comments, docs and commit messages.

## Adding an app

1. `look --window "<title>"` to see the labelled actionable elements.
2. Write the flow with `act … --append tapes/<flow>.yaml`, one passing step at a time.
3. When the flow repeats, move its selectors into `maps/<app>.yaml` and refer to them as `@name`, with the
   app version and the facts you had to learn as `notes`.
